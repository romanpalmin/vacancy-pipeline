# vacancy-pipeline

Мультиагентный конвейер разбора вакансий для Claude Code: сырой текст
вакансии → структурированная сводка → симуляция формального фильтра
hh.ru → содержательная оценка соответствия → сопроводительное письмо.
Три специализированных субагента + один переиспользуемый скилл,
оркестрированные одним скиллом-дирижёром.

## О проекте

Ну, не знаю, насколько внятно это звучит со стороны — но по сути это
не «персональный ИИ-агент нового поколения» в том раздутом смысле,
который сейчас пытаются пришить к любому скрипту из трёх строк (было
бы, честно говоря, чистой воды натягиванием маркетинговой совы на
инженерный глобус), а гораздо более скромная вещь: конвейер из трёх
узкоспециализированных субагентов, которые по очереди разбирают одну
вакансию. Сначала вытаскивают из сырого текста то, что реально важно —
не то, что вынесено в заголовок, а то, что зарыто в третьем абзаце
обязанностей. Потом симулируют формальный фильтр hh.ru — тот самый, на
котором отклик может не пройти то ли из-за формального стажа, то ли
из-за буквального совпадения skills-тегов, то ли просто потому что
зарплатная вилка не сошлась, а причина об этом никогда не сообщается
напрямую. И только потом — содержательная оценка: откликаться или нет,
и почему.

Задача, которую это решает, довольно приземлённая: разбирать вакансии
вручную по одной и той же схеме пять раз в день — это не столько
скучно, сколько к десятому одинаковому тексту подряд начинает
ощущаться уже не скукой, а вполне физической тупой болью где-то в
районе затылка. Дальше можно было бы долго рассуждать, то ли это
экономия времени, то ли просто способ не сойти с ума от однообразия —
но это, кажется, тот случай, когда оба объяснения верны одновременно,
и спорить об этом смысла нет :)

## Как это устроено

Модель — строго последовательная. Субагенты не видят историю чата друг
друга: весь протокол передачи состояния — обычные файлы в папке
вакансии. Можно было бы назвать это примитивным решением, а можно —
вполне сознательным архитектурным выбором в духе старой Unix-философии
«текстовый файл как универсальный интерфейс между процессами», тут уж
как посмотреть.

```
vacancy-raw.md  →  vacancy-summary.md  →  filter-check.md  →  match-analysis.md  →  cover-letter.txt
   (вход)          [vacancy-summarizer]   [filter-checker]     [match-analyst]     [vacancy-cover-letter]
```

**Шаг 1 — `vacancy-summarizer`.** Разбирает `vacancy-raw.md`, пишет
`vacancy-summary.md`: компания, зарплата, must-have/nice-to-have стек,
честные признания работодателя между строк, вероятный формат
интервью.

**Шаг 2 — `filter-checker`.** Симулирует формальный фильтр hh.ru
(стаж, заголовок резюме, буквальные skills-теги, зарплата, формат
работы, гражданство) — построчный вердикт + итоговое
ПРОЙДЁТ/НЕ ПРОЙДЁТ/ПОД ВОПРОСОМ.

**Гейт качества 1.** Если вердикт — НЕ ПРОЙДЁТ или ПОД ВОПРОСОМ,
пайплайн останавливается и явно уточняет, продолжать ли — не идёт
самостоятельно, автоматически объезжая проблему стороной.

**Шаг 3 — `match-analyst`.** Содержательная оценка (не по ключевым
словам): что переносится напрямую, что переносится с оговоркой, где
честный пробел, калибровка зарплаты — и рекомендация «откликаться» /
«откликаться с доработкой» / «пропустить».

**Гейт качества 2.** Если рекомендация — «пропустить», письмо не
пишется вообще. Пример `ivi-time-2026-08-20` в `examples/` — как раз
такой случай: три шага отработали, гейт остановил конвейер до того,
как появился четвёртый файл.

**Шаг 4 — `vacancy-cover-letter`** (переиспользуемый скилл, не
субагент). Пишет `cover-letter.txt` только если рекомендация — «за».
Формат под hh.ru (без markdown, обычные переносы строк), содержание —
конкретная зацепка за домен компании + 3–5 буллетов под требования
именно этой вакансии, без выдуманных цифр.

## Структура репозитория

```
.claude/
  agents/                     # три субагента
    vacancy-summarizer.md
    filter-checker.md
    match-analyst.md
  skills/
    vacancy-pipeline/          # скилл-оркестратор (вызывает трёх субагентов по очереди)
      SKILL.md
    vacancy-cover-letter/      # переиспользуемый скилл шага 4
      SKILL.md
examples/                      # два реальных прогона, оба ветки гейтов
  evrone-senior-fullstack-2026-08-05/   # полный путь: все 4 файла, письмо написано
  ivi-time-2026-08-20/                  # гейт 2 остановил пайплайн, письма нет
assets/                        # скриншоты работы
```

## Примеры

- **`evrone-senior-fullstack-2026-08-05`** — полный happy path.
  Рекомендация «откликаться с честным пробелом», письмо реально
  сгенерировано (честно называет отсутствие коммерческого опыта с
  PHP/Laravel, не пытается это спрятать).
- **`ivi-time-2026-08-20`** — гейт 2 в деле. Три наложенных
  экосистемных разрыва плюс зарплата ниже порога → рекомендация
  «пропустить» → `cover-letter.txt` не создаётся, пайплайн
  останавливается сам, без дополнительной команды.

Контактные данные (телефон/email) в подписи писем в обоих примерах
заменены плейсхолдером — не потому что сами вакансии/резюме нужно
было прятать, а чтобы номер телефона не разошёлся по интернету через
публичный репозиторий без особой на то причины.

## Как запустить у себя

1. Скопировать `.claude/agents/` и `.claude/skills/` в проект с Claude
   Code.
2. Создать папку вакансии с файлом `vacancy-raw.md` (сырой текст
   вакансии).
3. Попросить Claude Code прогнать вакансию по пайплайну — скилл
   `vacancy-pipeline` сам вызовет трёх субагентов по очереди и
   остановится на гейтах, если нужно.

**Честная оговорка:** субагент `match-analyst` на шаге 3 в оригинале
сверяется с резюме/профилем кандидата (`resume/`, `profile/`,
`prep/domain-touchpoints.md` в родительском проекте WorkHunter) — эти
файлы личные и в этот репозиторий не переносились. Для чужого резюме
пути и структуру этих файлов нужно будет завести самостоятельно —
готового «подставь своё резюме и работай» из коробки здесь нет, это
не тот масштаб.

## Происхождение и статус

Родился как ДЗ №6 курса «Вайб-кодинг на Claude Code» (скилл
`vacancy-cover-letter`, шаг 4), вырос до полного оркестратора с тремя
субагентами на ДЗ №10 (модуль 4, урок «Субагенты» — принято куратором:
«инженерный цикл развития продукта, а не просто домашка»). В реальной
работе используется ежедневно для разбора вакансий в личном поиске
работы — это не синтетический учебный пример, а рабочий инструмент,
которым автор пользуется каждый день. Этот репозиторий — упаковка
уже существующего и проверенного кода под финальный проект курса.
