## О продукте/проекте

Компания занимается зарядным оборудованием для электротранспорта: проектирование и реализация проектов зарядных станций, участник Сколково, федеральных и региональных программ. Продукты зарегистрированы в Минцифры и используются электромобилистами и владельцами зарядных станций. Компания существует с 2016 года, на стадии активного роста. Судя по описанию задач — цифровая экосистема вокруг зарядных станций: бэкенд-платформа + веб-интерфейс + мобильное приложение для конечных пользователей/операторов.

## Стек — must-have (обязательные, явно требуемые)

Из описания задач (не из тегов hh.ru):

- Node.js (серверная часть)
- MongoDB (проектирование структуры БД)
- Express, Mongoose (фреймворк и ORM)
- RESTful API — создание и оптимизация
- React (вёрстка, интеграция компонентов, оптимизация производительности, отладка и тестирование UI)
- React Native (мобильные приложения — новые экраны/компоненты, интеграция с бэкендом и внешними сервисами, отладка на iOS/Android)
- Участие в планировании/оценке задач, написание технической документации

**Отдельное замечание (важно для filter-check):** блок «Ключевые навыки» (теги hh.ru), который реально фигурирует на странице вакансии и по которому вероятнее всего идёт формальный отбор, включает: Java, HTML, Python, Node.js, PHP, «Разработка архитектуры ПО», Git, JavaScript, SaaS, API, ReactJS, «Английский язык», Frontend, Software Development. Этот список явно шире и не совпадает с текстом описания задач (нет упоминания Java/Python/PHP в теле вакансии) — похоже на шаблонный/не до конца вычищенный набор тегов, возможно скопированный с другой вакансии компании. Стоит учитывать при filter-check как источник формальных тегов, но не как реальные требования к стеку.

Прямых признаний про технический долг, отсутствие тестов, нестабильный legacy и т.п. в тексте нет — вакансия написана в основном в позитивном/рекламном тоне («быстрые согласования, отсутствие бюрократии», «карьерный и личностный рост»). Из показательного:

## Вероятный формат интервью и вероятные темы

Формальных указаний на этапы или тестовое задание в тексте нет. Исходя из размера компании (стадия роста, Сколково-стартап, не крупный энтерпрайз) и формулировки «Ведущий Fullstack developer», вероятный формат:

1. Скрининг с HR/руководителем (может совмещаться с техническим — в маленьких командах часто один-два этапа).
2. Техническое интервью с тем, кто ведёт разработку сейчас (вероятно, обсуждение архитектуры Node.js/Express/Mongoose-бэкенда, работы с MongoDB, опыта с React и React Native одновременно — учитывая тройной стек, вероятны вопросы на то, как кандидат распределяет фокус между бэком/вебом/мобайлом).
3. Тестовое задание не упомянуто явно, но с учётом позиции «Ведущий» и небольшой команды не исключено практическое задание или обсуждение реального кейса вместо формального тестового.

AI/LLM-инженерных требований в вакансии не обнаружено — задачи вакансии не затрагивают LLM API, RAG, агентов, промпт-инжиниринг как дисциплину и т.п., соответственно `prep/ai-engineer-requirements.md` не дополнялся.

## Первое впечатление (1-2 предложения, до формального анализа)

Небольшая растущая нишевая компания (зарядная инфраструктура для электротранспорта) ищет одного разработчика на весь стек сразу (Node.js-бэкенд + React-веб + React Native-мобайл) под должность «Ведущий» — при этом зарплатная вилка скромная для такого объёма ответственности; текст вакансии рекламный и не даёт технической конкретики, а теги hh.ru явно не соответствуют описанию задач, что настораживает по качеству составления вакансии.
